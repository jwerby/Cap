# Secure AWS S3 + CloudFront

This guide configures the default Cap bucket for private S3 storage and CloudFront signed read URLs. Uploads should continue to use direct S3 presigned URLs.

3. Serve default-bucket reads through CloudFront signed URLs only when all required env vars are present.
4. Reject partial or insecure CloudFront config at startup.
5. Document private S3, OAC, trusted key group, HTTPS, encryption, and least-privilege IAM setup.
6. Add a dry-run-first operator script for default-bucket thumbnail backfill.

Redeploy the app after changing the secret store so the runtime picks up the new values.

## AWS Resources

1. Create or update the S3 bucket.
   - Enable Block all public access.
   - Set Object Ownership to Bucket owner enforced.
   - Enable default encryption. Use SSE-S3 at minimum; use SSE-KMS when the app IAM principal and CloudFront OAC have key access.
   - Add a bucket policy that denies non-TLS access.
   - Allow `s3:GetObject` only from the CloudFront distribution through `AWS:SourceArn`.
   - Configure CORS for only required web origins and `GET`, `HEAD`, `POST`, and `PUT`.

2. Create the CloudFront distribution.
   - Origin: S3 bucket regional domain name.
   - Origin access: Origin Access Control with signing behavior `always` and SigV4.
   - Viewer protocol policy: redirect HTTP to HTTPS.
   - Allowed methods: `GET`, `HEAD`, `OPTIONS`.
   - Signed URL enforcement: trusted key group with the CloudFront public key.
   - TLS: use `TLSv1.2_2021` or newer with a custom certificate and media domain.
   - HTTP versions: enable HTTP/2 and HTTP/3.

3. Configure signing keys.
   - Generate an RSA key pair outside the repo.
   - Store the private key only in the app secret store.
   - Upload the public key to CloudFront and attach it to a trusted key group.
   - Rotate by adding a new public key, updating app env, then removing the old key after old signed URLs expire.

## App Environment

Set all four CloudFront env vars together. Partial config fails startup instead of silently falling back to S3 reads.

```bash
CAP_AWS_BUCKET_URL=https://<media-domain>
CAP_CLOUDFRONT_DISTRIBUTION_ID=<distribution-id>
CLOUDFRONT_KEYPAIR_ID=<cloudfront-public-key-id>
CLOUDFRONT_KEYPAIR_PRIVATE_KEY='-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----'
```

Keep uploads direct to S3:

```bash
S3_PUBLIC_ENDPOINT=https://s3.us-east-1.amazonaws.com
S3_INTERNAL_ENDPOINT=https://s3.us-east-1.amazonaws.com
S3_PATH_STYLE=false
CAP_VIDEOS_DEFAULT_PUBLIC=false
```

## Thumbnail Backfill

Dry run first:

```bash
pnpm with-env node scripts/backfill-missing-thumbnails.mjs --limit 25
```

Apply one video:

```bash
pnpm with-env node scripts/backfill-missing-thumbnails.mjs --video-id <video-id> --apply
```

Apply a batch:

```bash
pnpm with-env node scripts/backfill-missing-thumbnails.mjs --limit 50 --apply
```

The script only handles default-bucket videos. It skips custom bucket/storage-integration rows, existing thumbnails, and videos missing `result.mp4`.
